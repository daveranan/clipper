# R1 — Canvas-Based Video Surface (Phase 1 Implementation Notes)

- **Status:** ready to implement (Phase 1 of `docs/canvas-plan.md` only; Phases 2–6 deliberately NOT included)
- **Date:** 2026-08-16
- **Files touched:** `src/App.tsx`, `src/index.css` (nothing else)

## 1. Scope

Implements requirement **R1**: "Video displayed on a `<canvas>` with highest-quality preview (native-resolution buffer)".

**In scope**

- Keep the existing `<video>` (playback, audio, seeking) but hide it visually (1px, `opacity: 0`, `pointer-events: none`). **Not** `display: none` (it suspends frame rendering and `drawImage` would go blank).
- Keep a hidden `<img>` bound to `previewSrc` as the still source; its `onLoad` marks the canvas dirty.
- Add a visible `<canvas>`:
  - Internal buffer = media native size (`videoWidth/Height` or `naturalWidth/Height`), capped at 16384px per side.
  - CSS size = contain-fit rect inside the viewer, computed from the layer size (ResizeObserver) and media native size.
  - Draw loop (`requestAnimationFrame`): while playing / C-scrubbing, draw the video every frame; while paused, draw the still once via a dirty flag (no wasted compositing).
- Remove the direct display of `.viewer-video` / `.viewer-still` (elements remain as hidden sources).
- Keep `.empty-viewer` outside the canvas layer (placeholder, not media).

**Out of scope (later phases — do NOT add any of this in Phase 1)**

- Pan/zoom state (`viewerZoom`/`viewerPan`), wheel/middle-drag/keyboard handlers, `.viewer-canvas-layer` transform wrapper (Phase 2).
- Zoom toolbar buttons / % readout (Phase 3).
- `imageDisplayBounds` switch to `clientWidth/clientHeight`, `zoom` prop on `CropOverlay`, pointer-button guards (Phase 4).
- Perf polish beyond the dirty-flag drawing already required here (Phase 5).
- Full manual verification pass (Phase 6) — but build + lint must pass for this phase.

**Acceptance (from plan):** preview looks identical to today at 100% zoom; playback, frame stepping, C-scrub, and exact frames all work; no visible quality loss.

### 2.3 Crop overlay math (unchanged by this phase)

- `CropOverlay` (line ~2335): `.crop-layer` is `position: absolute; inset: 0` inside `.viewer`; it has its own ResizeObserver + `window resize` listener that bumps a `layoutVersion`.
- `imageDisplayBounds(element, sourceWidth, sourceHeight)` (line ~2642): `getBoundingClientRect` of the crop layer + contain math against **source** dimensions (`clip.width/clip.height`).
- `cropDisplayRect` (line ~2655): maps `crop` (source pixels) to layer-local px via that bounds.
- Drag math divides client deltas by `bounds.width / sourceWidth`.

**Why the crop overlay stays aligned with the canvas in Phase 1:** the canvas CSS size is the contain-fit rect of the *media native size*; the crop overlay computes the contain-fit rect of the *source size*. Because the playback source and exact frames preserve source resolution (see 2.5), media native size == `clip.width/height`, and both contain rects are the same rectangle (same aspect ⇒ same contain rect even for the 1280-wide cache frames). Subpixel differences between `getBoundingClientRect` and `clientWidth` already exist today (video `object-fit: contain` vs crop math) and are not a regression.

### 2.5 Rust side — what resolution each media source has (`src-tauri/src/lib.rs`)

| Source | Command | Resolution of output |
|---|---|---|
| Playback source | `prepare_playback_source` (~line 317) | **Native** — libx264 veryfast/CRF 12 re-encode with no scale filter (or the original file untouched when `is_browser_safe_playback`). |
| Exact frame | `extract_exact_frame` (~line 354) | **Native** — single JPEG, `-frames:v 1`, no scaling. |
| Preview cache frames | `prepare_preview_cache` (~line 282) | **1280px wide** — `-vf fps=…,scale=1280:-2` (upscales small sources, downscales large ones). |

**This is the key finding for buffer sizing:** the paused still is usually a 1280-wide JPEG, while the video is native (e.g. 4K). The canvas buffer must therefore be sized from the **video's** native size when available; the still is a lower-res stand-in that gets drawn into the native buffer.

## 3. Design decisions (with rationale)

- **D1 — Video stays mounted, hidden at 1px/opacity 0.** `display: none` suspends frame rendering in Chromium/WebView2 and `drawImage` would return blank. 1px + `opacity: 0` + `pointer-events: none` keeps decoding/rendering alive while being visually offscreen.
- **D2 — Hidden `<img>` remains the still source.** It is conditionally rendered exactly as today (`previewSrc && …`), so it unmounts during playback (same as today) and its `onLoad` is the dirty signal for the canvas.
- **D3 — Buffer size = media native size, video preferred.** `viewerMediaSize` is set from `video.videoWidth/videoHeight` on `loadedmetadata` (authoritative), and from `img.naturalWidth/naturalHeight` on `onLoad` **only when the video has no size yet** (covers playback-prep-failed clips where the still is the only media). Capped at 16384px/side (proportional downscale only for >16K sources).
  - *Why not size the buffer to the currently displayed media (switch 4K↔1280 on play/pause)?* It would give a marginally cleaner single-resample for the 1280 cache frames, but forces buffer resizes + redraws on every play/pause for a difference that is not visible (both paths use high-quality filtering). Rejected for complexity.
- **D4 — CSS size = contain-fit computed in JS.** A ResizeObserver on `.viewer` stores `viewerSize`; `viewerCanvasStyle = { width, height }` is the contain rect of `viewerMediaSize` inside `viewerSize` (fractional px are fine). The canvas is a flex child of `.viewer`, so it is centered without extra CSS. This mirrors the `object-fit: contain` layout exactly, so the 100%-zoom preview is pixel-identical in placement.
- **D5 — Draw loop: continuous rAF only while playing / C-scrubbing; one-shot dirty draw when paused.** "Dirty" is expressed as effect dependencies: any of `previewSrc` (new still URL), `viewerDrawTick` (bumped by `onLoad`/`onSeeked`/`onLoadedMetadata`), `viewerMediaSize` (buffer resize), `viewerCanvasStyle` (viewer resize), `clipMediaSrc` (new source) schedules exactly one rAF draw. No continuous rAF while paused ⇒ no wasted compositing.
- **D6 — Draw source priority** (updated after first manual test — see §9):
  1. Playing and video drawable → draw video.
  2. C-scrubbing and still drawable → draw still (the preview-cache frame following the cursor; the video lags behind in-flight seeks and is never drawn while C-scrubbing).
  3. Paused, `exactFrame` set, still drawable → draw still (native exact frame).
  4. Paused, video **current** (settled on the requested time: `!seeking`, `readyState >= 2`, `|video.currentTime − currentTime| ≤ 0.1s`) → draw video (native-resolution paused preview, 1:1 into the native buffer).
  5. else still drawable → draw still (cache frame, e.g. while a seek is in flight).
  6. else video drawable and the canvas has no painted content → draw video (covers the "preparing" state where the video is the only visible media today).
  7. else the canvas has no painted content → `clearRect` (true empty state: clip switch / preparing).
  8. else (a new still is loading) → **skip drawing** so the canvas keeps its last painted frame (no flicker between background and new image).
  - "Drawable" for video = `readyState >= 2 && videoWidth > 0`.
  - `viewerHasContentRef` tracks whether the canvas has painted content; it is reset on buffer resize and on `clipMediaSrc` change (both clear/replace the painted frame).
- **D7 — `.empty-viewer`** rendered only when `!previewSrc && !clipMediaSrc` (same visible states as today, without the `opacity: 0` trick). It stays a direct child of `.viewer`, outside any canvas layer.
- **D8 — No `image-rendering` CSS on the canvas.** Default browser filtering is what we want: high-quality downsample when displayed smaller, true pixels when (Phase 2) zoomed past 100%.
- **D9 — Nothing in `CropOverlay` / `imageDisplayBounds` / `cropDisplayRect` changes.** Phase 4 owns those.
- **D10 — View state is not introduced.** No `viewerZoom`/`viewerPan` in this phase; the structure (canvas centered in `.viewer`, crop layer absolute inset 0) is already Phase-2-ready: the future `.viewer-canvas-layer` (absolute inset 0, `transform-origin: 0 0`) will contain the same canvas + CropOverlay, and `viewerCanvasStyle` (contain rect of the layer) stays valid because the layer is the same size as `.viewer`.

### Step 1 — New refs and state

Anchor: immediately after the existing `const playbackRef = useRef<HTMLVideoElement | null>(null)` line (~180).

```tsx
const viewerCanvasRef = useRef<HTMLCanvasElement | null>(null)
const viewerSurfaceRef = useRef<HTMLDivElement | null>(null)

const [viewerMediaSize, setViewerMediaSize] = useState<{ width: number; height: number } | null>(null)

```

Notes:

- `viewerMediaSize` = native size of the media (D3). `viewerSize` = `.viewer` layout size.
- `viewerDrawTick` is the dirty flag; `bumpViewerDraw` is called from media events.

### Step 2 — Derived canvas CSS size

Anchor: after the `clipMediaSrc` memo (~line 302).

```tsx
const viewerCanvasStyle = useMemo(() => {
  if (!viewerMediaSize || !viewerSize) {
    return { width: 0, height: 0 }
  }
  const scale = Math.min(
    viewerSize.width / Math.max(1, viewerMediaSize.width),
    viewerSize.height / Math.max(1, viewerMediaSize.height),
  )
  return {
    width: viewerMediaSize.width * scale,
    height: viewerMediaSize.height * scale,
  }
}, [viewerMediaSize, viewerSize])
```

`{ width: 0, height: 0 }` keeps the canvas invisible until media size is known (no flash, no 300×150 default).

### Step 3 — Viewer size observer

Anchor: right after `viewerCanvasStyle`.

```tsx
useEffect(() => {
  const surface = viewerSurfaceRef.current
  if (!surface) {
    return
  }
  const measure = () => setViewerSize({ width: surface.clientWidth, height: surface.clientHeight })
  measure()
  if (typeof ResizeObserver === 'undefined') {
    return
  }
  const observer = new ResizeObserver(measure)
  observer.observe(surface)
  return () => observer.disconnect()
}, [])
```

### Step 4 — Canvas buffer sizing (native resolution, 16384 cap)

Anchor: after the size-observer effect.

```tsx
useEffect(() => {
  const canvas = viewerCanvasRef.current
  if (!canvas || !viewerMediaSize) {
    return
  }
  const cap = 16384
  const scale = Math.min(1, cap / viewerMediaSize.width, cap / viewerMediaSize.height)
  const width = Math.max(1, Math.round(viewerMediaSize.width * scale))
  const height = Math.max(1, Math.round(viewerMediaSize.height * scale))
  if (canvas.width !== width || canvas.height !== height) {
    canvas.width = width
    canvas.height = height
  }
  bumpViewerDraw()
}, [bumpViewerDraw, viewerMediaSize])
```

Assigning `canvas.width` clears the bitmap, hence the `bumpViewerDraw()` (the one-shot draw effect in Step 7 repaints).

### Step 5 — Reset media size when the clip source changes

Anchor: after the buffer-sizing effect.

```tsx
useEffect(() => {
  setViewerMediaSize(null)
}, [clipMediaSrc])
```

On a new clip the old native size is stale; the canvas hides (Step 2 returns 0×0) and clears (Step 6 fallback) until the new `loadedmetadata` / still `onLoad` arrives. On mount this is a no-op (already `null`).

### Step 6 — Draw function

Anchor: after Step 5.

```tsx
const drawViewerFrame = useCallback(() => {
  const canvas = viewerCanvasRef.current
  if (!canvas || canvas.width === 0 || canvas.height === 0) {
    return
  }
  const context = canvas.getContext('2d')
  if (!context) {
    return
  }
  const video = playbackRef.current
  const still = viewerStillRef.current
  const videoDrawable = Boolean(video && video.readyState >= 2 && video.videoWidth > 0)
  const stillDrawable = Boolean(still && still.complete && still.naturalWidth > 0)
  if ((isPlaying || isCScrubbing) && videoDrawable) {
    context.drawImage(video, 0, 0, canvas.width, canvas.height)
  } else if (stillDrawable) {
    context.drawImage(still, 0, 0, canvas.width, canvas.height)
  } else if (videoDrawable) {
    context.drawImage(video, 0, 0, canvas.width, canvas.height)
  } else {
    context.clearRect(0, 0, canvas.width, canvas.height)
  }
}, [isCScrubbing, isPlaying])
```

`drawImage` scales source → buffer; when buffer == native size this is a 1:1 copy (no quality loss). The 1280 cache still is upscaled into the native buffer by the browser's high-quality filter (D3).

### Step 7 — Continuous draw loop (playing / C-scrubbing only)

Anchor: after `drawViewerFrame`.

```tsx
useEffect(() => {
  if (!isPlaying && !isCScrubbing) {
    return
  }
  let frame = 0
  const tick = () => {
    drawViewerFrame()
    frame = requestAnimationFrame(tick)
  }
  frame = requestAnimationFrame(tick)
  return () => cancelAnimationFrame(frame)
}, [drawViewerFrame, isCScrubbing, isPlaying])
```

This runs in parallel with the existing playback `tick` (which owns `currentTime` advancement) — the two loops are independent; do not merge them.

### Step 8 — One-shot dirty draw (paused)

Anchor: after the continuous-loop effect.

```tsx
useEffect(() => {
  if (isPlaying || isCScrubbing) {
    return
  }
  const frame = requestAnimationFrame(drawViewerFrame)
  return () => cancelAnimationFrame(frame)
}, [clipMediaSrc, drawViewerFrame, isCScrubbing, isPlaying, previewSrc, viewerCanvasStyle, viewerDrawTick, viewerMediaSize])
```

Each dependency is a "dirty" condition: new still URL (`previewSrc`), image finished loading / video seeked / metadata (via `viewerDrawTick`), buffer or CSS size change, new clip source. Exactly one draw per change; no rAF churn while idle.

## 5. Behavior matrix (expected after implementation)

| State | `previewSrc` | `clipMediaSrc` | Canvas draws | Visible placeholder |
|---|---|---|---|---|
| No clip | null | null | cleared (0×0 CSS) | `.empty-viewer` |
| Preparing (clip loading) | null | maybe | video if ready, else cleared | hidden (matches today) |
| Paused, cache frame | cache URL | yes | video (native) once its seek settles; cache still (1280 → native buffer) only while a seek is in flight | no |
| Paused, exact frame | exact URL | yes | still (native, 1:1) after `onLoad` | no |
| Playing | null | yes | video every rAF (1:1) | no |
| C-scrubbing | cache URL (or exact) | yes | cache still every rAF (follows the cursor); keeps last painted frame while the next frame loads | no |
| Playback prep failed | cache/exact URL | null | still | no |

Transient races (all self-correcting, final state correct):
- `previewSrc` changes before the new `<img>` finishes loading → canvas **keeps the last painted frame** (skip-draw) until `onLoad` → `bumpViewerDraw` → redraw with the new still. No flash to background or stale video.
- C-scrub: the still stays mounted (`previewSrc` is not nulled); each pointermove re-targets the cache frame; the lagging video is never drawn while C-scrubbing.
- New `clipMediaSrc` before new `loadedmetadata` → `viewerHasContentRef` reset → canvas cleared; reappears at correct size when metadata lands.
- Still loads before video metadata (or vice versa) → `viewerMediaSize` updates to the video size when it arrives (video is authoritative, D3), buffer resizes, redraw.

## 7. Risks / edge cases (assessed)

1. **1280 cache frames in a native buffer** — the paused cache-frame preview is now upscaled into the native buffer and then downscaled to display size (two high-quality resamples) instead of one. Visually indistinguishable in practice; exact frames and playback remain 1:1. Accepted (D3).
2. **`display: none` trap** — avoided by design (D1); do not "simplify" the 1px/opacity hiding later.
3. **WebView2** — Phase 1 adds no keyboard/wheel handlers, so no new page-zoom or passive-listener issues (those are Phase 2 territory).
4. **8K+ sources** — 16384px/side cap keeps buffers within platform limits (~33MB RGBA at 8K, acceptable on desktop per plan).
5. **Subpixel crop alignment** — canvas contain rect from `clientWidth/Height` vs crop overlay from `getBoundingClientRect`: same relationship as today's `object-fit` video vs crop math; no regression (Phase 4 formalizes this with `clientWidth/clientHeight`).
6. **`<img>` unmount during playback** — same conditional rendering as today; `viewerStillRef` goes null; the canvas keeps its last painted frame until the video draws (video is the live source while playing).
7. **Stale frame on clip switch** — `viewerHasContentRef` reset on `clipMediaSrc` change + media-size reset (Step 5) → canvas cleared until the new source paints.

## 9. Post-implementation fixes (after first manual test)

First test run surfaced three issues; all fixed in `src/App.tsx` only (no Rust, no CSS):

1. **C-scrub showed no preview while scrubbing** — `previewSrc` nulled the still during `isCScrubbing`, unmounting the `<img>` and leaving the canvas with only the lagging video (its seeks were always in flight). Fix: `previewSrc` no longer nulls during C-scrub (only during playback), and the draw loop draws the preview-cache still while C-scrubbing — the same "fast frame skip" behavior as timeline drag. The video is still seeked for positioning and is drawn once it settles after C-scrub ends.
2. **Flicker between background and new image** — the old fallback chain drew the stale video frame or `clearRect`ed while a new still was loading (`img.complete === false` after a `src` swap). Fix: `viewerHasContentRef` + skip-draw — while paused and the new still is not yet drawable, the canvas keeps its last painted content; `clearRect` runs only in the true empty state (nothing drawable and nothing painted yet, e.g. clip switch / preparing).
3. **Preview not HD enough** — the paused still is a 1280px cache frame upscaled into the native buffer. Fix (frontend only, no Rust / cache-resolution change): when paused, a video that has **settled** on the requested time (`!seeking`, `readyState >= 2`, `|video.currentTime − currentTime| ≤ 0.1s`) is drawn instead of the cache still — its frame is native resolution and lands 1:1 in the native buffer. The paused preview is therefore native after playback pause, seek settle, and C-scrub settle; exact frames (native) still take priority while set. Cache frames remain the only source during active scrubbing, where the video lags by design.
